# 可读性规则

适用于全部自有代码，新增和实际修改部分先执行；边界与等级见 [规则入口](README.md)。清晰度由读者能否理解职责、状态和失败行为判断，不以短名比例、注释数量或函数长度替代。

### R-READABILITY-01 名称表达职责与领域事实

- **等级：MUST。**
- **范围：** 自有类型、文件、函数、参数、变量、字段、常量与脚本导出项。
- **要求：** 名称保留必要的动作、角色、单位与状态信息，并沿用所在模块的命名风格和领域术语。小作用域可用 `i` 等常见索引；跨边界名称应自说明。`Cfg` 在本项目已有控制流图含义，不能机械把 `Config/Configuration` 缩为 `Cfg`；同样不强制 `Context`→`Ctx` 等全仓缩写。
- **例外：** C API、标准入口、override、SDK、注册字符串与外部协议名称保留合同。项目统一短类型依照 [类型规则](type_naming_rules.md)，不视为随意缩写。
- **验证：** 人工检查声明和调用处的含义；改名搜索代码、字符串注册、构建列表、脚本入口与文档，不只依赖编译器引用查找。

### R-READABILITY-02 注释优先说明调用合同

- **等级：MUST。**
- **范围：** 存在非显然调用约束的类型、函数、回调和借用接口。
- **要求：** 在声明附近说明职责及必要的所有权、有效期、失败后状态、栈效果、重入/yield、线程或副作用约束；无独立声明时在定义附近说明。共同合同集中维护，其他位置链接或补充差异；实现处就近解释不可由结构表达的原因。
- **例外：** 自说明的简单访问器、转发函数或局部步骤无需重复注释；已在所属类型或权威接口明确的共同合同不逐函数复制。语言、模板或工具要求的位置优先保持合法。
- **验证：** 人工对照调用方和实现核对准确性，行为修改时同步更新；不强制所有函数中文注释，也不以添加空泛说明满足规则。

### R-READABILITY-03 函数按阅读路径组织

- **等级：SHOULD。**
- **范围：** 类型声明、模块入口、实现与 helper。
- **要求：** 优先按生命周期、公开入口、主流程与细节组织；只服务局部的 helper 保持最窄可见范围。头文件与实现的主要分组便于相互定位。
- **例外：** C++ 声明依赖、模板、初始化顺序和 Lua 局部绑定可决定顺序；不为入口置顶制造无意义前置声明或改变作用域。
- **验证：** 人工沿调用链检查阅读成本与名称查找，重排后验证语言绑定和初始化行为。

### R-READABILITY-04 嵌套与长度是调查信号

- **等级：REVIEW。**
- **范围：** 难以局部理解、混合多个抽象层或正常路径被遮蔽的流程。
- **要求：** 检查完整职责能否用卫语句或子流程更清楚地表达；说明实际理解障碍，再决定是否拆分。
- **例外：** opcode 表、天然层级遍历和严格时序流程可保持集中；不因达到某行数、参数数或嵌套层数自动拆分。
- **验证：** 人工比较改动前后的阅读路径与边界；提取不能遗漏清理、复制状态或改变遍历顺序，详见 [重构规则](refactoring_rules.md)。

### R-READABILITY-05 条件与副作用能够直接读出

- **等级：SHOULD。**
- **范围：** 含结果解包、多重取反或多个抽象层的条件。
- **要求：** 有独立含义时命名操作结果或提取只读谓词；简单空值、范围、枚举和清楚的复合条件可就地保留。一次插入、一次执行或可能触发 Lua 回调的操作应让副作用可见。
- **例外：** 提前提取会改变短路、调用次数、借用有效期或失败时机时保留原路径，并按需解释；换行本身不要求提取函数。
- **验证：** 人工逐分支检查求值与副作用；不得提前执行原本受空值检查保护的成员访问。

### R-READABILITY-06 薄封装有明确边界价值

- **等级：REVIEW。**
- **范围：** 只转发一次调用或很短的 wrapper。
- **要求：** 检查其是否承载语义、校验、错误转换、能力约束、兼容或测试边界；没有职责时考虑简化调用路径。
- **例外：** C ABI 包装、平台差异、allocator 路由与 protected 边界即使很薄也可以保留；不能以“一行函数”为由删除。
- **验证：** 人工核对调用方减少了哪些知识依赖，以及内联是否扩大能力、改变异常或资源合同。

### R-READABILITY-07 签名保留必要信息

- **等级：SHOULD。**
- **范围：** 长签名、同类型多参数与领域别名。
- **要求：** 保留有意义的参数名与角色信息，按配置折行。领域别名表达稳定概念；需要防止不同 ID 混用时评估真正的强类型，不把 `using` 别名视为隔离机制。
- **例外：** 契约规定的名称和类型优先保留；`auto` 和模板推导清楚时可使用，不为减少字符删去 `const` 或改变传参方式。
- **验证：** 人工对照完整签名与调用方，检查参数顺序、单位、所有权和错误语义。

### R-READABILITY-08 文件与类型说明各自职责

- **等级：SHOULD。**
- **范围：** 新文件、新类型及职责发生变化的现有代码。
- **要求：** 在文件开头简述职责和必要边界；类型说明状态归属与不变量，字段按需说明单位、范围和特殊值。说明实际已实现内容，避免复制符号清单、版本口号或架构正文。
- **例外：** 自说明的小型测试 fixture、数据文件或生成产物可由所在说明/生成源承载；shebang、编码声明和许可证保留必要位置。
- **验证：** 人工检查说明与实际职责一致；不为补头注释翻译全部历史说明或扩大本次修改范围。

### R-READABILITY-09 注释准确且有信息量

- **等级：MUST。**
- **范围：** 本次新增或修改的注释与待办。
- **要求：** 使用团队可理解且前后一致的语言，准确保留技术名称、来源和工具指令；解释原因、限制与失败条件，不逐行翻译代码。待办指出具体缺口与完成条件。过期注释随行为更新或移除。
- **例外：** 第三方许可证、来源固定注释和 `NOLINT` 等工具文本保持原文；不要求全量中文，也不允许以翻译为由删除重要信息。
- **验证：** 人工检查真实性、位置与必要性；没有自动注释质量检查器，搜索英文单词不能判断违规。
