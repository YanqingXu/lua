# PR-01 GC 拆分实施计划

> **给 agentic workers：** 必须使用子技能：推荐使用 `superpowers:subagent-driven-development`，也可使用 `superpowers:executing-plans`，并按任务逐项执行本计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 将 `src/gc/garbage_collector.cpp` 拆分为聚焦 GC 生命周期各阶段的源文件，同时保持 `GarbageCollector` 公共接口和运行时行为不变。

**架构：** 保留 `garbage_collector.cpp` 作为对象所有权和收集流程编排文件，将阶段性成员函数定义移动到 `gc_mark.cpp`、`gc_sweep.cpp`、`gc_finalize.cpp` 和 `gc_weak.cpp`。PR-01 不引入新的 GC strategy 抽象；本 PR 是一次机械式结构拆分，为 PR-08 以及后续 GC 重构预留边界。

**技术栈：** C++20/C++23、MSVC 项目文件、CMake 静态库目标 `lua_core`、自定义 `lua_test.exe` 测试运行器。

## 逻辑拆分

### `garbage_collector.cpp`

保留当前职责所需的 include：

```cpp
#include "gc/garbage_collector.hpp"
#include "core/gc_string.hpp"
#include "core/string_pool.hpp"
#include "core/table.hpp"
#include "core/userdata.hpp"
#include <algorithm>
#include <iostream>
```

此文件继续保留以下方法定义：

```text
GarbageCollector::getInstance()
GarbageCollector::GarbageCollector()
GarbageCollector::~GarbageCollector()
GarbageCollector::registerObject(GCObject*)
GarbageCollector::unregisterObject(GCObject*) noexcept
GarbageCollector::addRoot(GCObject*)
GarbageCollector::removeRoot(GCObject*)
GarbageCollector::isRoot(GCObject*) const
GarbageCollector::collect()
GarbageCollector::collect(LuaState*)
GarbageCollector::getObjectCount() const noexcept
GarbageCollector::getRootCount() const noexcept
GarbageCollector::getTotalMemory() const noexcept
GarbageCollector::getStatistics(...)
GarbageCollector::clearAll()
GarbageCollector::printStatistics() const
```

`collect(LuaState*)` 的阶段顺序必须保持等价：

```cpp
usize GarbageCollector::collect(LuaState* currentState) {
    mark(currentState);

    if (currentState != nullptr) {
        prepareFinalizers();
        propagateMarks();
    }

    clearWeakTableEntries();

    usize collected = sweep();
    weakTables_.clear();

    if (currentState != nullptr) {
        runFinalizers(currentState);
    }

    return collected;
}
```

### `gc_mark.cpp`

将原匿名 namespace 中的 helper 改为 private static class helper，这样 `gc_weak.cpp` 也可以复用它们。在 `garbage_collector.hpp` 的 `GarbageCollector` private 区域新增声明：

```cpp
static bool valueContainsObject(const Value& value);
static GCObject* objectFromValue(const Value& value);
```

在 `gc_mark.cpp` 中实现：

```cpp
#include "gc/garbage_collector.hpp"
#include "core/function.hpp"
#include "core/gc_string.hpp"
#include "core/table.hpp"
#include "core/thread.hpp"
#include "core/upvalue.hpp"
#include "core/userdata.hpp"
#include "core/value.hpp"
#include "vm/global_state.hpp"
#include "vm/lua_state.hpp"
#include <algorithm>

namespace Lua {

bool GarbageCollector::valueContainsObject(const Value& value) {
    return value.isString() || value.isTable() || value.isFunction() ||
           value.isUserdata() || value.isThread();
}

GCObject* GarbageCollector::objectFromValue(const Value& value) {
    if (value.isString()) {
        return value.asString();
    }
    if (value.isTable()) {
        return value.asTable();
    }
    if (value.isFunction()) {
        return value.asFunction();
    }
    if (value.isUserdata()) {
        return value.asUserdata();
    }
    if (value.isThread()) {
        return value.asThread();
    }
    return nullptr;
}

} // namespace Lua
```

随后将这些现有方法原样移动到 helper 后面：

```text
GarbageCollector::mark()
GarbageCollector::mark(LuaState*)
GarbageCollector::propagateMarks()
GarbageCollector::markObject(GCObject*)
GarbageCollector::markValue(const Value&)
GarbageCollector::markState(LuaState*)
```

关键不变量：`mark(LuaState*)` 仍然必须在标记 roots 前清空 `grayList_` 和 `weakTables_`，并且仍然必须在 `propagateMarks()` 前标记 `pendingFinalizers_`。

### `gc_sweep.cpp`

使用尽量窄的 include 集合：

```cpp
#include "gc/garbage_collector.hpp"
#include "core/gc_string.hpp"
#include "core/string_pool.hpp"
```

将 `GarbageCollector::sweep()` 原样移动到该文件。保持以下顺序：

1. 保存 `next`。
2. 检查 `GCBits::FIXED`。
3. 从链表中摘除 white 且非 fixed 的对象。
4. 调整 `totalMemory_` 和 `objectCount_`。
5. 如果对象是字符串，从 `StringPool` 中移除。
6. 执行 `delete obj`。
7. 将存活对象重置为 white，为下一轮 GC 做准备。

PR-01 不移动 `clearAll()`。它是测试 / 调试清理 helper，不属于正常 sweep 阶段。

### `gc_finalize.cpp`

使用终结器执行所需的 include：

```cpp
#include "gc/garbage_collector.hpp"
#include "core/gc_string.hpp"
#include "core/table.hpp"
#include "core/userdata.hpp"
#include "core/value.hpp"
#include "vm/global_state.hpp"
#include "vm/lua_state.hpp"
#include "vm/stack.hpp"
#include "vm/vm.hpp"
```

将以下方法原样移动到该文件：

```text
GarbageCollector::getFinalizer(Userdata*) const
GarbageCollector::prepareFinalizers()
GarbageCollector::runFinalizers(LuaState*)
```

关键不变量：

- `prepareFinalizers()` 只为 white、非 fixed、未 finalized，且拥有非 nil `__gc` 的 userdata 排队。
- 它必须设置 `GCBits::FINALIZED`，将 userdata 放入 `pendingFinalizers_`，并调用 `markObject(obj)`。
- `runFinalizers()` 必须保留 `finalizersRunning_` 防重入保护，将待执行列表 swap 到局部 vector，恢复 Lua 栈 / 调用状态，并吞掉 finalizer 异常。

### `gc_weak.cpp`

使用弱模式检测和死亡值判断所需的 include：

```cpp
#include "gc/garbage_collector.hpp"
#include "core/gc_string.hpp"
#include "core/table.hpp"
#include "core/value.hpp"
#include "vm/global_state.hpp"
```

将以下方法原样移动到该文件：

```text
GarbageCollector::markTable(Table*)
GarbageCollector::isObjectDead(GCObject*) const
GarbageCollector::isValueDead(const Value&) const
GarbageCollector::clearWeakTableEntries()
```

关键不变量：

- `markTable()` 仍然通过 `GlobalState::getInstance().getMetamethodName(TMS::TM_MODE)` 从表元表中读取 `__mode`。
- 弱模式 bit 必须通过 `table->getMarked() & ~GCBits::WEAKBITS` 刷新。
- 弱表必须在调用 `table->markContents(*this, weakKeys, weakValues)` 前记录到 `weakTables_`。
- `clearWeakTableEntries()` 必须在 `collect(LuaState*)` 中先于 `sweep()` 执行。

## PR 验收标准

- `GarbageCollector` public 方法和调用点保持源码兼容。
- `collect(LuaState*)` 的阶段顺序保持不变。
- 弱表清理仍然先于 `sweep()` 执行。
- finalizer 准备仍然发生在第二次 `propagateMarks()` 之前，finalizer 执行仍然发生在 sweep 之后。
- CMake 和 Visual Studio 静态库源文件清单包含四个新的 `.cpp` 文件。
- `lua_test.vcxproj` 继续通过 `ProjectReference` 使用 `lua.vcxproj`。
- 完整测试运行器退出码为 `0`，并输出 `Failed: 0`。
