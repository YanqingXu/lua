# Bytecode Tool Guide

`lua_bytecode.exe` compiles Lua scripts and prints the generated `Proto` bytecode.

Current status is useful for bytecode inspection and lightweight bytecode comparison:

- `src/bytecode/bytecode_main.cpp` reads one script for print mode or two scripts for `--diff`, parses them, generates `Proto` objects, and calls the printer API.
- `src/bytecode/bytecode_printer.cpp` prints the Proto header, decoded instructions, constant references, the constant table, and recursive child protos in full mode.
- `printProtoBytecodeDiff()` renders both sides, ignores source-path metadata noise, and prints only changed lines in a side-by-side diff table.

So the target is useful for bytecode inspection across closures and for comparing two generated bytecode listings, but it is not yet a CFG visualizer.

## Usage

```powershell
bin\lua_bytecode.exe examples\hello.lua
bin\lua_bytecode.exe examples\hello.lua full
bin\lua_bytecode.exe examples\before.lua examples\after.lua --diff
bin\lua_bytecode.exe examples\before.lua examples\after.lua --diff full
```

`full` enables recursive child Proto output. Compact mode prints only the top-level Proto; both modes annotate `CLOSURE` with the referenced `proto[index]` summary.

`--diff` compiles both scripts in the same runtime service and compares the rendered bytecode output. Plain `--diff` compares the compact top-level listing; `--diff full` includes recursive child Proto sections. The left and right file names are shown as labels, while `source:` path metadata is ignored during comparison so identical bytecode in different files is still reported as identical.

## Current Data Flow

```text
script path
  -> readWholeFile()
  -> Parser
  -> CodeGenerator
  -> Proto*
  -> printProtoBytecode(...)

left/right script paths
  -> readWholeFile()
  -> Parser
  -> CodeGenerator
  -> Proto*
  -> printProtoBytecodeDiff(...)
```

## Current Output

The current printer shows:

- source name
- parameter count and vararg flag
- `maxStackSize`
- constants
- line info
- each instruction with decoded `A/B/C/Bx/sBx`
- constant comments for `LOADK`, RK operands, and jump targets
- `CLOSURE` comments with child proto references
- recursive child protos in full mode
- `--diff` summary fields: left label, right label, mode, status, and changed lines
- `--diff` side-by-side rows for changed rendered bytecode lines
