# String Pool — 字符串池与GC

## 1. StringPool 与 GC 的关系

```
StringPool 持有所有 GCString 的强引用。

驻留字符串不会被 GC 回收:
  - StringPool 内部持有引用
  - 即使没有 Value 引用该字符串
  
这意味着:
  - 字符串越多 → 内存越大
  - 字符串不会被释放 (除非 StringPool 主动清理)
```

## 2. 为什么字符串不回收

```
设计原因:
  1. 驻留字符串需要全局唯一 → 必须保存
  2. 字符串通常较小且重复使用 → 回收收益低
  3. 简化 GC 逻辑

权衡:
  ✓ 字符串比较快 (指针比较)
  ✓ 内存节约 (相同字符串只存一份)
  ✗ 所有字符串常驻内存
```

## 3. 未来改进

```
可能的改进方向:
  - 短字符串常驻，长字符串按需回收
  - StringPool 使用弱引用 + GC 回收不常用的字符串
  - 参考 Lua 5.2+ 的做法
```
