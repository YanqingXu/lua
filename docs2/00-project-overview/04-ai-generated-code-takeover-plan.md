# AI-Generated Code Takeover Plan

## 1. 这个模块解决什么问题？

本项目大量代码由 AI 辅助生成。这份文档说明**如何从"AI 生成的代码"转变为"自己掌控的代码"**。

## 2. 接管策略

### 阶段 1：建立心智模型（当前阶段）

```
目标：能看懂每行代码在做什么
方法：
1. 阅读 docs2 文档，建立全局认知
2. 用一个简单 Lua 脚本追踪全流程
3. 画出模块调用关系图
4. 阅读每个模块的核心函数
```

### 阶段 2：验证理解

```
目标：能预测代码行为
方法：
1. 读一段 Lua 代码，手动推导 Token 流
2. 手动推导生成的字节码
3. 手动推导 VM 执行过程
4. 用实际输出验证预测
```

### 阶段 3：能独立修改

```
目标：能新增功能和修复 Bug
方法：
1. 先改简单的（如新增一个标准库函数）
2. 再改中等的（如修复一个 VM 指令 bug）
3. 最后改复杂的（如新增一个语法特性）
```

## 3. 学习路径

### 第一周：看懂执行链路

```
1. 阅读 docs2/01-execution-pipeline/08-full-trace-example.md
2. 用调试器单步执行 hello.lua
3. 关注：Token 怎么生成、AST 长什么样、字节码怎么执行
```

### 第二周：看懂核心模块

```
1. 阅读 Value/Table/Function 的实现
2. 阅读 VM 主循环的执行逻辑
3. 阅读 GC 的标记-清除流程
4. 关注：每个模块的输入输出、数据结构、函数调用链
```

### 第三周：能改代码

```
1. 尝试新增一个简单的标准库函数
2. 尝试修改一个 VM 指令的行为
3. 尝试新增一个词法规则
4. 关注：改了哪里、测试是否通过
```

## 4. 关键理解点（必须吃透）

| 序号 | 概念 | 为什么重要 |
|------|------|-----------|
| 1 | Proto vs Closure vs Function 的区别 | 函数系统的核心 |
| 2 | Upvalue Open/Closed 状态转换 | 闭包正确性的关键 |
| 3 | VM 栈布局（func/base/top） | 理解函数调用和返回 |
| 4 | RK 寻址（寄存器 vs 常量） | 理解所有算术指令 |
| 5 | CallInfo 的 savedpc | 理解函数调用链恢复 |
| 6 | Table 数组部分 vs 哈希部分 | 理解表操作的性能 |
| 7 | GC 三色标记流程 | 理解内存管理 |

## 5. 实用技巧

### 调试技巧
```
1. lua_app --trace 可以输出指令级执行轨迹
2. lua_bytecode 可以打印编译后的字节码
3. REPL 中 .bytecode 可以查看交互式编译结果
4. .gc 可以查看 GC 状态
```

### 代码导航技巧
```
1. 从测试文件入手理解模块行为
2. 从 .hpp 文件了解接口
3. 从 .cpp 文件了解实现细节
4. 从 CMakeLists.txt 了解文件依赖关系
```

### 修改前必做
```
1. 跑一遍现有测试，确保全绿
2. 找到你要改的代码位置
3. 理解现有代码为什么这样写
4. 明确你的改动期望什么效果
5. 写完跑测试，确保不引入回归
```
